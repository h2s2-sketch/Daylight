Daylight · v0.3 — Final UI Direction

This is what Daylight looks like.

One committed direction, ready for build. Soft Sunrise gives the warmth and the single glowing action; Calm Focus gives the structure — clear hierarchy, scannable lists, real readability; and the Personal Journal lends exactly one thing: a Weekly Review that feels like closing the week, not filling a form. Same five screens, same loop, same four tables. No new features.

Design system

The shared rules every screen obeys. Warm ground, one accent reserved for action, cool category hues, a confident type hierarchy, and a single permitted glow.

Button & surface style

Primary
Gold→Sun gradient, 14px radius, one soft glow (see below). One per screen.
Done state
White fill, sun-ink text, faint glow ring — calm, not a trophy.
Review
Solid ink-blue ("like a pen"); no glow.
Surfaces
Hairline rules over cards. White only for sheets, goal cards, the review banner. Everything else floats on the warm ground, divided by warm hairlines.
Radius
14–16px on surfaces, 7px on toggles, pill for chips.

Rules for using glow

Check in for today Second glow
  • Exactly one glowing element per screen — always the primary action.
  • Glow = a soft box-shadow ring in sun-soft + one drop shadow. Static. Never animated, never pulsing.
  • The dashboard's one sun-glow wash sits behind the greeting only — it is part of the ground, not a second glow.

Rules for avoiding over-design

  • No drawn suns, rays, or decorative illustration. The warmth comes from colour and light, not graphics.
  • No full-screen gradients beyond the dawn wash. One subtle vertical wash, then flat paper.
  • No motion except the sheet sliding up and a quiet fade. Nothing bounces.
  • No streak, flame, badge, confetti. The quiet mono "4 / 7 this week" is the only metric.
  • If it doesn't help a tired person act or reflect, it's not on the screen.

Layout
Linear 3 steps with a thin progress bar: Looking back (score each focus) → Reflecting (3 written questions) → Next week (pick ≤3, carry forward).
Visual
The Journal detail: serif step titles, an italic evening dateline, and reflection questions over faint ruled writing lines. Ink-blue buttons. Flat paper — a desk to write on.
Main action
One per step: Continue → Continue → Close the week.
Components
StepBar · LookBackItem×3 (Done/Partial/Missed) · JournalQuestion×3 · NextWeekSlot · CarryChip

06 — Hand-off

Final handoff notes

The rules a coding assistant must hold to keep this direction intact. Build the loop thin and warm; resist everything not listed.

  1. Tokens first. Define the palette, category enum, and type families as CSS variables exactly as in §00. Ground = dawn→paper wash on scroll screens, flat paper on focused tasks (Focus, Review, Goals).
  2. One glow, one accent. The Gold→Sun gradient + soft glow ring is .cta only — one per screen. Category colours are cool and never use the accent. No second glow anywhere.
  3. Type hierarchy is the structure. Newsreader (greetings, review), Public Sans 700/800 (titles, buttons, focus), IBM Plex Mono (dates, counts, labels, "moved Nd"). Hairline rules replace cards.
  4. Weekly count, never streak. count(daily_checkins this week) → "N / 7 this week", mono, muted, top-right. No streak logic, flame, or badge in the codebase.
  5. Focus progress is words. "Moved N days" = count of this week's check-ins whose progressed_focus_ids includes the focus id. Never render a denominator or "N/?".
  6. Check-in is a sheet, idempotent per date; only the focus toggles are required. Target < 60s. Don't add fields.
  7. Review is the journal moment. Three steps, ink-blue buttons, serif questions over CSS ruled lines (plain textareas beneath), evening dateline, "Close the week". Map answers to wins / slipped / learning. Target 3–5 min. No satisfaction score.
  8. Focus cap = 3, enforced UI + API; hide the add affordance at 3 and show the cap line. Carry-forward clones the focus onto the next week_start.
  9. Goals stay one line. One active per category, fixed 7-key enum, status chip only. No description field, no detail page.
  10. Hold the "not present" lists. Each screen's spec names what must not appear. When unsure, leave it out — the warmth and calm come from restraint, not addition. Touch targets ≥ 44px.
The bar for done: a tired person opens Daylight at 9pm, checks in in under a minute, and on Sunday closes the week in a few minutes feeling it was worth it — for several weeks running. Warm, calm, practical. Not impressive — repeatable.
